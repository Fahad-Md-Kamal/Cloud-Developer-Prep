# 🧠 Problem Solving Rehab Plan (Engineer Edition)

This plan is designed for experienced software engineers who feel rusty with algorithmic problem solving. It focuses on **pattern recognition, retention, and transfer to real-world engineering**, not competitive grinding.

---

## 🎯 Goals

* Rebuild algorithmic confidence
* Recognize problem patterns quickly
* Reduce cognitive load during interviews
* Translate DSA → real backend/system use cases

Time commitment: **45–60 minutes/day**
Duration: **12 weeks**

---

# 📅 12-Week Structured Roadmap

## Phase 1: Pattern Foundation (Weeks 1–3)

Focus: *Core patterns, Easy → Medium only*

### Must-master patterns

* Two pointers
* Sliding window
* Hash map / frequency counting
* Prefix sum
* Binary search (on index & answer)

### Weekly routine

* Mon–Thu: 1 problem/day
* Fri: Re-solve 2 old problems from memory
* Sat: Review notes + mistakes
* Sun: OFF

Platforms: LeetCode (free), InterviewBit

---

## Phase 2: Structural Thinking (Weeks 4–6)

Focus: *Trees, graphs, recursion, basic DP*

### Patterns

* DFS vs BFS
* Tree traversal (inorder/pre/post)
* Backtracking
* 1D DP (state, transition, base case)

Rule: Always write **brute force first**, then optimize.

---

## Phase 3: Optimization & Depth (Weeks 7–9)

Focus: *Performance + constraints*

### Topics

* Heaps & priority queues
* Greedy algorithms
* Binary search on answer
* Interval problems

Add constraint analysis before coding.

---

## Phase 4: Endurance & Transfer (Weeks 10–12)

Focus: *UVa / Codeforces style + interview readiness*

* 2 problems/week from UVa / SPOJ / AtCoder
* Timed practice (45 mins)
* Post-solution write-up mandatory

---

# 🧩 Pattern Cheat Sheet (Engineer-Friendly)

## Sliding Window

**Use when:** subarray / substring with condition

Backend analogy:

* Rate limiting
* Rolling metrics

---

## Two Pointers

**Use when:** sorted array / linked list

Backend analogy:

* Merge streams
* Pagination cursors

---

## Hash Map Counting

**Use when:** frequency, uniqueness

Backend analogy:

* Deduplication
* Aggregations

---

## BFS / DFS

**Use when:** graph / tree / state space

Backend analogy:

* Dependency resolution
* Workflow engines

---

## Dynamic Programming

**Key question:** Can this be broken into overlapping subproblems?

Backend analogy:

* Caching layers
* Memoized computations

---

# 🔁 Problem Solving Template (Use Every Time)

1. Restate problem in your own words
2. Write brute force solution
3. Identify bottleneck
4. Name the pattern
5. Optimize
6. Re-solve after 3 days

---

* Problem solving is a **trainable skill**, not intelligence
* Seniority ≠ algorithm speed
* Consistency beats intensity
