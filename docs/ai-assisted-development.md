# AI-Assisted Development Tools & Workflows

**Status: placeholder.** Flagged from the Svea Solar Senior Fullstack
Engineer (Django) JD gap analysis (2026-09-23) — the JD calls this out
twice ("we embrace AI-assisted development," bonus point for
"curious about AI-assisted development tools and workflows"). This is
distinct from the existing
[AI & LLM System Integration](index.md#ai-llm-system-integration)
section, which is about *building* AI-powered products — this is
about *using* AI coding assistants (Copilot, Cursor, Claude Code) as
your own development practice. Nothing on the site currently covers
this angle. Not yet given the full Q&A deep-dive treatment this site's
other chapters have.

**Topics to cover when this gets deep-dived:**

- Tools landscape: autocomplete-style assistants (Copilot) vs.
  agentic/CLI assistants (Cursor, Claude Code, Windsurf) — what each
  is actually good at.
- Effective prompting and workflow patterns for AI pair programming —
  what makes a session productive vs. a time sink.
- Code review discipline for AI-generated code: verifying correctness
  and intent, not rubber-stamping output that "looks right."
- Where AI assistance helps most (boilerplate, tests, refactors,
  exploring an unfamiliar codebase) vs. where it's genuinely risky
  (security-sensitive logic, subtle business rules).
- Team practices: PR review standards when part of a diff was
  AI-written, disclosure norms, avoiding a two-tier review process.
- Security/IP considerations — what it means to send proprietary code
  to a third-party AI service, and how teams manage that.
- Interview framing: "walk me through your actual daily workflow with
  an AI coding assistant" — a concrete answer, not a generic
  enthusiasm statement.
